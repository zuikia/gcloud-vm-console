# GCP VM Console UI Product Redesign

## 目标与边界

本轮把现有 gcloud-only 控制台重构为成熟、紧凑、可预测的本地云运维产品。视觉参考 AIHOT 的深色空间层次、克制青色光影、紧凑侧栏和清晰排版，但不复制其内容站布局，也不引入霓虹、装饰光球或大面积玻璃效果。

本轮只修改本地 UI、前端交互、测试和模拟数据。不得执行真实 GCP 创建、修改、停止、重启或删除操作，不得恢复 Terraform、ADC、Profile、plan/apply/workspace 等产品概念。

## 信息架构

主导航保持四项：

1. **总览**：账号项目上下文、资源摘要、当前 VM、最近任务、唯一推荐动作。
2. **VM**：统一资源表格、选中对象详情、维护操作和折叠危险区。
3. **配置**：新建、编辑、基于现有 VM 新建共用一套表单。
4. **任务**：置顶运行日志、只读任务历史、选中任务进度、变更预览、节点链接和原始错误。

顶部上下文栏在四页保持稳定，只显示当前账号/项目、同步状态、刷新和新建 VM。账号与项目的选择控件只在总览出现；切换下拉选项不等于切换有效上下文。

## 页面结构

### 总览

- 第一层：页标题、服务状态、账号与项目选择。
- 第二层：账号、项目、VM 总数、运行中四项紧凑指标带。
- 第三层：当前 VM 为主区，下一步为强调区，最近任务为横向低权重区。
- 费用、安全和免费规则合并为默认折叠的辅助区域。
- 不显示连接信息，不使用营销 Hero。
- 2026-06-18 精修：账号/项目选择、服务状态和四项指标合并为“运营状态”面板，减少重复入口，并在桌面端横向铺满主要工作区。

### VM

- 桌面端以统一表格为主，账号/项目、名称、区域、状态、公网 IP、部署类型均在行内可辨识。
- 点击行只选择资源。详情作为表格下方的资源检查器显示，不能回退成固定右侧长侧栏；“配置此 VM”为主操作，“基于此新建”作为明确次操作，不放入只有一项的更多菜单。
- 维护操作按“检查、运行维护、部署”分组，危险操作固定在底部折叠区。
- 900px 以下改为带字段标签的分组行；移动端详情在表格下方。
- 2026-06-18 精修：详情区拆成基础信息、网络信息、身份信息三段，未选中 VM 时只显示紧凑空状态。
- 2026-06-18 修正：固定右侧长详情栏会造成“左上小表格 + 右侧长侧栏”的失衡布局，已改为表格优先、详情下置。未选中 VM 时隐藏配置、维护和危险操作区，避免空状态下面堆禁用按钮。

### 配置

- 标题区明确显示“新建 / 编辑 / 基于现有新建”模式。
- 主列默认只显示核心字段：名称、区域、可用区、系统、机器、磁盘和部署方式。
- 网络、SSH、标签和 startup script 放入一个高级折叠区，避免短字段把页面拉散。
- 右侧为执行摘要，只显示目标、模式、关键变更、风险/费用提示和预览状态；不镜像整张表单。
- “保存草稿”为次操作，“保存并生成预览”为主操作。
- 字段修改立即使旧预览失效；startup script 内容参与 desired hash，避免脚本变更被预览忽略；移动端严格单列。

### 任务

- 首屏先显示运行日志，日志高度固定在 216–252px 范围内，内部滚动。
- 日志下方是只读任务历史表格，数据来自 `GET /api/jobs`，按创建时间倒序排列。
- 选中任务后显示阶段进度、变更预览、执行结果、可重试提示、原始错误和节点链接。
- 删除旧的“节点结果/当前结果”侧栏，避免同一结果在任务页重复出现。
- 长节点链接显示协议、端口、标签和复制操作，原始链接在自己的横向滚动容器中。

## 视觉系统

### Token

- 画布：深蓝黑，不使用纯黑作为大面积页面背景。
- 面板：比画布提高一个明度层级；浮层再提高一个层级。
- 边框：默认、强调、聚焦、危险四种语义。
- 文本：主、次、弱、禁用四层，所有正文在面板背景上达到 WCAG AA。
- 状态：青色主操作、绿色成功、琥珀警告、红色危险。
- 浅色主题保留完整语义 token，不在组件中硬编码主题颜色。

### 光影

- 页面顶部使用低透明度径向环境光，不形成可见光球。
- 选中导航使用内侧边缘高光和极弱外发光。
- 面板仅在顶部边缘保留一条微弱高光；普通卡片不使用大阴影。
- 聚焦控件使用 2px 可辨识焦点环；光效不降低文字对比度。

### 排版与密度

- 字体栈：Inter、SF Pro、PingFang SC、系统无衬线字体。
- 正文 14px，辅助 12px，面板标题 16px，页标题 26px；字间距统一为 0。
- 控件高度 38px，紧凑控件 32px，表格行高约 58px，触摸目标最小 44px。
- 桌面主内容横向内边距 28px，宽度 100%，使用 12 列网格；不设置导致右侧空洞的窄 max-width。
- 圆角采用 6px 或 8px；不使用胶囊形文本按钮，状态 badge 除外。

## 组件规则

- 每页最多一个强调按钮。
- 面板不嵌套面板；连续数据优先使用表格、描述列表、分隔线和背景分区。
- 空状态保持紧凑，说明原因并提供唯一下一步。
- 所有异步按钮进入统一 busy 状态，保留原标签，显示阶段文本，并阻止重复提交。
- Toast 只报告结果；持续进度显示在触发任务的页面内。
- 只读和本地保存不弹确认；云端写入说明对象、费用和网络影响；危险操作要求明确确认。

## 任务数据模型

- `GET /api/jobs` 是只读接口，只返回本地任务历史，不提供 POST 或 DELETE 管理入口。
- 前端使用 `task-view-model.js` 将 job 转换为任务行、阶段、结果和耗时，避免 DOM 直接理解后端原始结构。
- 任务行字段固定为 `任务 / VM / 时间 / 状态 / 耗时`。
- 失败任务保留原始错误文本，但错误文本必须在自身容器中换行或滚动。

## 响应式验收

- 1728、1440、1280：充分使用可用宽度，无右侧无意义空洞。
- 1024、768：多列逐步收敛，工具栏可换行，主操作保持可见。
- 390：完全单列，无横向页面滚动、文字竖排、控件裁切或小于 44px 的触摸按钮。
- 长项目 ID、IPv6、节点链接和错误文本只在自身容器换行或横向滚动。
- 路由切换回到页面顶部，不保留上一页滚动位置。
